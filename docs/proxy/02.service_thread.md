# Service Thread 详解

## 1. 核心定位

Service Thread 本质上是一个 **RPC 服务器**，监听来自其他 rank（包括自己）的请求，执行 transport 层的初始化和连接建立操作。

```
  Rank 0                           Rank 1                          Rank 2
┌──────────┐                    ┌──────────┐                    ┌──────────┐
│  Main    │                    │  Main    │                    │  Main    │
│ Thread   │                    │ Thread   │                    │ Thread   │
└────┬─────┘                    └────┬─────┘                    └────┬─────┘
     │                               │                               │
     │ ncclProxyConnect()            │                               │
     │ ncclProxyCallBlocking()       │                               │
     │       │                       │                               │
     │       │   TCP socket          │                               │
     │       └──────────────────────►│                               │
     │                          ┌────┴─────┐                         │
     │                          │ Service  │◄────────────────────────┘
     │                          │ Thread   │  来自 Rank 2 的请求
     │                          │ (Rank 1) │
     │                          └──────────┘
     │                               │
     │◄──────────────────────────────┘  返回响应
```

每个 rank 的 Service Thread 都可能收到来自任何其他 rank 的请求，包括自己。这是因为即使是本地通信，也需要通过 Service Thread 来分配 connection 资源。

## 2. 调用链

当 Rank A 需要与 Rank B 建立通信连接时，会触发以下调用链：

```
Rank A (客户端)                                  Rank B (服务端)
──────────────────                               ──────────────────
Main Thread                                      Service Thread
     │                                                │
     │  transport->sendSetup()                        │
     │       │                                        │
     ▼       ▼                                        │
ncclProxyConnect(proxyRank=B)                         │
     │  [proxy.cc:1121]                               │
     │                                                │
     │  1. 如果还没连接，建立 TCP 连接               │
     │     ncclSocketConnect(sock)  ─────────────────►│ ncclSocketAccept()
     │                                                │ 加入 peers[] 数组
     │                                                │
     │  2. 发送 ncclProxyMsgInit                     │
     │     ncclProxyCallBlocking()                    │
     │       │                                        │
     ▼       ▼                                        │
ncclProxyCallAsync()  [proxy.cc:1263]                 │
     │                                                │
     │  发送: type + connection + reqSize + respSize + reqBuff + opId
     │  ──────────────────────────────────────────────►│
     │                                                │
     │                                     proxyServiceInitOp()
     │                                          │  [proxy.cc:1549]
     │                                          ▼
     │                                     proxyProgressAsync()
     │                                          │  [proxy.cc:1491]
     │                                          ▼
     │                                     proxyConnInit()
     │                                          │  [proxy.cc:1422]
     │                                          │
     │                                          │  • 分配 connection

     │                                          │  • 首次时创建 Progress Thread

     │                                                │

ncclPollProxyResponse()                               │
     │  收到响应，保存 connection                     │
     │                                                │
     ▼                                                │
继续发送 Setup, Connect 消息...                       │
```

## 3. 消息格式

### 3.1 RPC 请求消息

客户端通过 `ncclProxyCallAsync`（proxy.cc:1263-1279）发送请求：

```
┌──────────┬─────────────┬──────────┬───────────┬──────────┬──────────┐
│   type   │ connection  │ reqSize  │ respSize  │ reqBuff  │   opId   │
│  (int)   │  (void*)    │  (int)   │   (int)   │ (bytes)  │ (void*)  │
│  4字节   │   8字节     │  4字节   │   4字节   │ 可变长度  │  8字节   │
└──────────┴─────────────┴──────────┴───────────┴──────────┴──────────┘

type: ncclProxyMsgInit / Setup / Connect / ...
connection: 哪个连接（Init 时为 NULL，后续消息指向已创建的连接）
reqBuff: 请求数据（如 transport 参数）
opId: 用于匹配异步响应
```

### 3.2 RPC 响应消息

服务端返回响应（proxy.cc:1528-1536）：

```
┌─────────────────────────────────────────┬──────────┐
│     ncclProxyRpcResponseHeader          │ respBuff │
├──────────┬──────────┬───────────────────┤  (bytes) │
│   opId   │   res    │     respSize      │ 可变长度  │
│ (void*)  │(ncclRes) │      (int)        │          │
│  8字节   │   4字节  │      4字节        │          │
└──────────┴──────────┴───────────────────┴──────────┘
```

## 4. 消息类型

Service Thread 处理的消息类型定义在 `proxy.h:401-414`：

| 消息类型 | 说明 | 触发的操作 |
|----------|------|-----------|
| `ncclProxyMsgInit` | 初始化连接 | `proxyConnInit()` - 创建 connection，首次时创建 Progress Thread |
| `ncclProxyMsgSharedInit` | 共享资源初始化 | `tcomm->proxySharedInit()` |
| `ncclProxyMsgSetup` | 配置 transport | `tcomm->proxySetup()` - 配置网络参数 |
| `ncclProxyMsgConnect` | 建立连接 | `tcomm->proxyConnect()` - 实际建立网络连接 |
| `ncclProxyMsgRegister` | 注册内存 | `tcomm->proxyRegister()` |
| `ncclProxyMsgDeregister` | 注销内存 | `tcomm->proxyDeregister()` |
| `ncclProxyMsgStop` | 停止服务 | 设置 stop 标志，准备退出 |
| `ncclProxyMsgClose` | 关闭连接 | 关闭当前 peer 的连接 |

## 5. 主循环详解

Service Thread 的主循环（proxy.cc:1606-1770）使用 `poll()` 多路复用来同时处理多个连接：

```c
void* ncclProxyService(void* _args) {
  struct ncclProxyState* proxyState = (struct ncclProxyState*) _args;

  // ========== 初始化 ==========
  struct ncclProxyConnectionPool connectionPool;  // 连接池
  struct pollfd pollfds[NCCL_MAX_PROXY_CONNECTIONS+1];  // poll 数组
  struct ncclProxyLocalPeer peers[NCCL_MAX_PROXY_CONNECTIONS];  // peer 信息

  // 最后一个 slot 是 listenSock
  pollfds[NCCL_MAX_PROXY_CONNECTIONS].fd = listenSock_fd;
  pollfds[NCCL_MAX_PROXY_CONNECTIONS].events = POLLIN;

  // ========== 主循环 ==========
  while (stop == PROXY_RUNNING || npeers > 0) {

    // 1. poll 所有连接（包括 listenSock）
    poll(pollfds, NCCL_MAX_PROXY_CONNECTIONS+1, timeout);

    // 2. 检查是否有新连接
    if (pollfds[NCCL_MAX_PROXY_CONNECTIONS].revents & POLLIN) {
      int s = find_free_slot();
      ncclSocketAccept(&peers[s].sock, proxyState->listenSock);
      pollfds[s].fd = peers[s].sock.fd;
      npeers++;
    }

    // 3. 处理每个 peer 的消息
    for (int s = 0; s < maxnpeers; s++) {
      if (pollfds[s].fd == -1) continue;

      // 3a. 推进该 peer 的异步操作
      ncclProxyAsyncOp* op = peer->asyncOps;
      while (op != nullptr) {
        proxyProgressAsync(op, ...);
        op = op->next;
      }

      // 3b. 检查是否有新消息
      if (pollfds[s].revents & POLLIN) {
        ncclSocketRecv(sock, &type, sizeof(int));

        switch (type) {
          case ncclProxyMsgInit:
          case ncclProxyMsgSetup:
          case ncclProxyMsgConnect:
          case ncclProxyMsgSharedInit:
          case ncclProxyMsgRegister:
          case ncclProxyMsgDeregister:
            proxyServiceInitOp(type, peer, ...);
            break;

          case ncclProxyMsgStop:
            stop = PROXY_STOP;
            closeConn = 1;
            break;

          case ncclProxyMsgClose:
            closeConn = 1;
            break;
        }
      }

      // 3c. 检查连接是否断开
      if (pollfds[s].revents & POLLHUP) {
        closeConn = 1;
      }

      if (closeConn) {
        ncclSocketClose(sock);
        pollfds[s].fd = -1;
        npeers--;
      }
    }
  }

  // ========== 清理 ==========
  ncclProxyProgressDestroy(proxyState);
  ncclProxyFreeConnections(&connectionPool, proxyState);
}
```

```
                    └────────┬─────────┘
                             │

                    │  poll() 多路复用  │ ◄── 同时监听多个连接
                    └────────┬─────────┘

```

## 6. 消息处理详解

每种消息类型都有对应的处理逻辑，在 `proxyProgressAsync`（proxy.cc:1491-1547）中分发：

```c
static ncclResult_t proxyProgressAsync(
    struct ncclProxyAsyncOp* op,
    struct ncclProxyState* proxyState,
    int* asyncOpCount,
    struct ncclProxyLocalPeer* peer,
    struct ncclProxyConnectionPool* connectionPool) {

  if (op->type == ncclProxyMsgInit) {
    // 初始化连接
    res = proxyConnInit(peer, connectionPool, proxyState,
                        (ncclProxyInitReq*) op->reqBuff,
                        (ncclProxyInitResp*) op->respBuff,
                        &op->connection);

  } else if (op->type == ncclProxyMsgSharedInit) {
    // 初始化共享资源
    int nChannels = (int) *op->reqBuff;
    if (op->connection->tcomm->proxySharedInit)
      res = op->connection->tcomm->proxySharedInit(op->connection, proxyState, nChannels);
    op->connection->state = connSharedInitialized;

  } else if (op->type == ncclProxyMsgSetup) {
    // 配置 transport
    res = op->connection->tcomm->proxySetup(op->connection, proxyState,
                                             op->reqBuff, op->reqSize,
                                             op->respBuff, op->respSize, &done);

  } else if (op->type == ncclProxyMsgConnect) {
    // 建立实际连接
    res = op->connection->tcomm->proxyConnect(op->connection, proxyState,
                                               op->reqBuff, op->reqSize,
                                               op->respBuff, op->respSize, &done);

  } else if (op->type == ncclProxyMsgRegister) {
    // 注册内存
    res = op->connection->tcomm->proxyRegister(op->connection, proxyState,
                                                op->reqBuff, op->reqSize,
                                                op->respBuff, op->respSize, &done);

  } else if (op->type == ncclProxyMsgDeregister) {
    // 注销内存
    res = op->connection->tcomm->proxyDeregister(op->connection, proxyState,
                                                  op->reqBuff, op->reqSize, &done);
  }

  if (done) {
    // 更新连接状态
    if (op->type == ncclProxyMsgSetup)
      op->connection->state = connSetupDone;
    else if (op->type == ncclProxyMsgConnect)
      op->connection->state = connConnected;

    // 发送响应
    ncclProxyRpcResponseHeader resp = {op->opId, res, op->respSize};
    ncclSocketSend(op->connection->sock, &resp, sizeof(resp));
    if (op->respSize)
      ncclSocketSend(op->connection->sock, op->respBuff, op->respSize);

    asyncProxyOpDequeue(peer, op);
  }

  return res;
}
```

## 7. proxyConnInit 详解

`proxyConnInit`（proxy.cc:1422-1447）是处理 `ncclProxyMsgInit` 的核心函数：

```c
static ncclResult_t proxyConnInit(
    struct ncclProxyLocalPeer* peer,
    struct ncclProxyConnectionPool* connectionPool,
    struct ncclProxyState* proxyState,
    ncclProxyInitReq* req,
    ncclProxyInitResp* resp,
    struct ncclProxyConnection** connection) {

  // 1. 从连接池分配一个新的 connection
  int id;
  ncclProxyNewConnection(connectionPool, &id);
  ncclProxyGetConnection(connectionPool, id, connection);

  // 2. 初始化 connection 字段
  (*connection)->sock = &peer->sock;
  (*connection)->transport = req->transport;  // P2P, NET, SHM, COLLNET...
  (*connection)->send = req->send;            // 发送方还是接收方
  (*connection)->tpLocalRank = req->tpLocalRank;
  (*connection)->sameProcess = req->sameProcess;

  // 3. 返回 connection 指针给客户端
  resp->connection = *connection;

  // 4. 设置 transport 的回调函数
  (*connection)->tcomm = (*connection)->send
      ? &ncclTransports[(*connection)->transport]->send
      : &ncclTransports[(*connection)->transport]->recv;

  // 5. 如果这个 transport 需要 proxy progress，初始化 ops pool 和 Progress Thread
  if ((*connection)->tcomm->proxyProgress) {
    proxyProgressInit(proxyState);  // 创建共享内存 + Progress Thread
    strncpy(resp->devShmPath, state->opsPoolShmSuffix, ...);
  }

  // 6. 标记连接已初始化
  (*connection)->state = connInitialized;

  return ncclSuccess;
}
```

## 10. 为什么需要 Service Thread

你可能会问：为什么不直接在 Main Thread 里做这些事？原因有几个：

1. **跨进程协调**：Rank A 需要让 Rank B 在它那边分配资源（如网络 buffer），这需要 RPC 机制

2. **异步执行**：网络连接建立是耗时操作，用独立线程可以不阻塞其他 rank

3. **资源隔离**：所有 proxy 相关的资源（connection pool、网络句柄）都在 Service Thread 管理，避免多线程竞争

4. **生命周期管理**：Service Thread 可以正确处理连接断开、abort 等异常情况
