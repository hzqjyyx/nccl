# 双向环形 AllGather（Bootstrap Step 5）

## 一、概述

### 为什么需要这一步？

经过 Bootstrap Step 1-4，每个 rank 已经建立了环形连接：

```
Rank 0 ──send──> Rank 1 ──send──> Rank 2 ──send──> Rank 0 (环形)
   ↑                                                  │
   └──────────────────recv────────────────────────────┘
```

**但现在的问题是**：每个 rank 只知道自己的地址信息（P2P 地址、Proxy 地址等），不知道其他 rank 的地址。后续建立实际的 GPU 通信通道时，rank 0 需要直接连接 rank 5，就必须知道 rank 5 的地址。

**Step 5 的目标**：让每个 rank 都获得所有其他 ranks 的地址信息——这就是一个 **AllGather** 操作。

### 核心思想

NCCL 使用**双向环形 AllGather**算法：数据同时向两个方向传播，步数减半。

| 方案 | 步数 | 说明 |
|------|------|------|
| 单向 Ring AllGather | N-1 步 | 数据只向一个方向传播 |
| **双向 Ring AllGather** | **N/2 步** | 数据同时向两个方向传播 |

## 四、核心逻辑

### socketRingAllGather 算法

```c
// bootstrap.cc:1428-1470（简化版）
static ncclResult_t socketRingAllGather(
    struct ncclSocket* nextSock,   // 发送给下一个 rank 的 socket
    struct ncclSocket* prevSock,   // 从上一个 rank 接收的 socket
    int rank, int nranks,
    char* data, int size           // data[i] 是 rank i 的数据块
) {
  int totalSteps = nranks / 2;     // 双向：只需 N/2 步

  for (int step = 0; step < totalSteps; step++) {
    // 偶数 ranks 的最后一步是单向的（避免重复传输）
    bool isFinalUnidirectional = (step == totalSteps - 1) && (nranks % 2 == 0);

    // Ring0: 顺时针方向（prev → next）
    int sendSliceRing0 = (rank - step + nranks) % nranks;      // 发给 next 的 slice
    int recvSliceRing0 = (rank - step - 1 + nranks) % nranks;  // 从 prev 收的 slice

    // Ring1: 逆时针方向（next → prev）
    int sendSliceRing1 = (rank + step) % nranks;               // 发给 prev 的 slice
    int recvSliceRing1 = (rank + step + 1) % nranks;           // 从 next 收的 slice

    if (isFinalUnidirectional) {
      // 最后一步只用 Ring0（单向）
      send(nextSock, data + sendSliceRing0 * size);
      recv(prevSock, data + recvSliceRing0 * size);
    } else {
      // 双向同时传输
      send(nextSock, data + sendSliceRing0 * size);  // Ring0: → next
      recv(prevSock, data + recvSliceRing0 * size);  // Ring0: ← prev
      send(prevSock, data + sendSliceRing1 * size);  // Ring1: → prev
      recv(nextSock, data + recvSliceRing1 * size);  // Ring1: ← next
    }
  }
}
```

## 五、完整示例（3 个 ranks）

### 环形拓扑

```
     Rank 0
    ↗      ↘
 Rank 2 ← Rank 1

next 方向: 0 → 1 → 2 → 0（顺时针）
prev 方向: 0 → 2 → 1 → 0（逆时针）
```

### 初始状态

```
            slot[0]    slot[1]    slot[2]
Rank 0:    [ A0 ]      [  ]       [  ]
Rank 1:    [  ]        [ A1 ]     [  ]
Rank 2:    [  ]        [  ]       [ A2 ]
```

### totalSteps = 3/2 = 1

只需要 1 步（奇数 ranks 不需要特殊处理最后一步）。

### Step 0 计算

| Rank | sendR0 (→next) | recvR0 (←prev) | sendR1 (→prev) | recvR1 (←next) |
|------|----------------|----------------|----------------|----------------|
| 0    | (0-0+3)%3 = **0** | (0-0-1+3)%3 = **2** | (0+0)%3 = **0** | (0+0+1)%3 = **1** |
| 1    | (1-0+3)%3 = **1** | (1-0-1+3)%3 = **0** | (1+0)%3 = **1** | (1+0+1)%3 = **2** |
| 2    | (2-0+3)%3 = **2** | (2-0-1+3)%3 = **1** | (2+0)%3 = **2** | (2+0+1)%3 = **0** |

### Step 0 数据流

```
Ring0 (顺时针: prev → next):
  Rank 0: 发送 slot[0]=A0 给 Rank 1，从 Rank 2 接收 slot[2]=A2
  Rank 1: 发送 slot[1]=A1 给 Rank 2，从 Rank 0 接收 slot[0]=A0
  Rank 2: 发送 slot[2]=A2 给 Rank 0，从 Rank 1 接收 slot[1]=A1

Ring1 (逆时针: next → prev):
  Rank 0: 发送 slot[0]=A0 给 Rank 2，从 Rank 1 接收 slot[1]=A1
  Rank 1: 发送 slot[1]=A1 给 Rank 0，从 Rank 2 接收 slot[2]=A2
  Rank 2: 发送 slot[2]=A2 给 Rank 1，从 Rank 0 接收 slot[0]=A0
```

### Step 0 完成后

```
            slot[0]    slot[1]    slot[2]
Rank 0:    [ A0 ]      [ A1 ]     [ A2 ]    ✓ 完成
Rank 1:    [ A0 ]      [ A1 ]     [ A2 ]    ✓ 完成
Rank 2:    [ A0 ]      [ A1 ]     [ A2 ]    ✓ 完成
```

**只用 1 步就完成了！** 传统单向 Ring 需要 2 步。

## 六、完整示例（4 个 ranks，偶数情况）

### 环形拓扑

```
  Rank 0 ─→ Rank 1
    ↑          ↓
  Rank 3 ←─ Rank 2
```

### 初始状态

```
            [0]     [1]     [2]     [3]
Rank 0:    [A0]     [ ]     [ ]     [ ]
Rank 1:    [ ]     [A1]     [ ]     [ ]
Rank 2:    [ ]     [ ]     [A2]     [ ]
Rank 3:    [ ]     [ ]     [ ]     [A3]
```

### totalSteps = 4/2 = 2

### Step 0（双向传输）

| Rank | sendR0 | recvR0 | sendR1 | recvR1 |
|------|--------|--------|--------|--------|
| 0    | 0      | 3      | 0      | 1      |
| 1    | 1      | 0      | 1      | 2      |
| 2    | 2      | 1      | 2      | 3      |
| 3    | 3      | 2      | 3      | 0      |

Step 0 后：

```
            [0]     [1]     [2]     [3]
Rank 0:    [A0]    [A1]     [ ]    [A3]    ← 缺 slot[2]
Rank 1:    [A0]    [A1]    [A2]     [ ]    ← 缺 slot[3]
Rank 2:     [ ]    [A1]    [A2]    [A3]    ← 缺 slot[0]
Rank 3:    [A0]     [ ]    [A2]    [A3]    ← 缺 slot[1]
```

### Step 1（单向传输，偶数特殊处理）

对于偶数 ranks，最后一步 `isFinalUnidirectional = true`：

```c
bool isFinalUnidirectional = (step == totalSteps - 1) && (nranks % 2 == 0);
// step=1, totalSteps=2, nranks=4 → true
```

**为什么是单向？** 在 Step 1：
- Ring0 想发送 slot[(rank-1+4)%4]
- Ring1 想发送 slot[(rank+1)%4]
- 对于某些 rank，这两个 slot 是相同的！双向会重复传输。

只使用 Ring0：

| Rank | sendR0 | recvR0 |
|------|--------|--------|
| 0    | 3      | 2      |
| 1    | 0      | 3      |
| 2    | 1      | 0      |
| 3    | 2      | 1      |

Step 1 后：

```
            [0]     [1]     [2]     [3]
Rank 0:    [A0]    [A1]    [A2]    [A3]    ✓
Rank 1:    [A0]    [A1]    [A2]    [A3]    ✓
Rank 2:    [A0]    [A1]    [A2]    [A3]    ✓
Rank 3:    [A0]    [A1]    [A2]    [A3]    ✓
```

## 七、交换的地址信息后续用途

### 1. peerP2pAddresses —— 用于后续 Bootstrap P2P 通信

`bootstrapSend/Recv` 函数需要知道目标 rank 的地址：

```c
// bootstrap.cc:1255-1266
static ncclResult_t socketConnect(void* commState, int peer, ...) {
  // 使用 peer 的 P2P 地址建立连接
  ncclSocketInit(sock, state->peerP2pAddresses + peer, ...);
  ncclSocketConnect(sock);
}
```

**后续使用场景**（`transport.cc:176-188`）：

```c
// 建立 GPU 通信通道时，交换连接信息（ncclConnect）
// 比如：NVLink 需要交换 GPU 句柄，InfiniBand 需要交换 QP 信息
bootstrapSend(comm->bootstrap, recvPeer, tag, connectInfo, size);
bootstrapRecv(comm->bootstrap, sendPeer, tag, connectInfo, size);
```

### 2. peerProxyAddresses —— 用于 Proxy 线程通信

Proxy 线程处理网络操作，避免阻塞 CUDA kernel：

```c
// proxy.cc:1845
ncclResult_t ncclProxyInit(comm, sock, peerAddresses, ...) {
  comm->proxyState->peerAddresses = peerAddresses;
  // Proxy 线程需要和其他 rank 的 Proxy 通信时，使用这些地址
}
```

**工作流程**：

```
Rank 0 GPU kernel 想发送数据给 Rank 1
        │
        ▼
Rank 0 Proxy 线程 ──(peerProxyAddresses[1])──> Rank 1 Proxy 线程
        │                                           │
        ▼                                           ▼
   处理网络发送                                  处理网络接收
```

### 3. peerProxyAddressesUDS —— 节点内优化

当两个 rank 在同一台机器上时，用 Unix Domain Socket 比 TCP 更快。

### 4. rasRanks —— 监控和故障恢复

RAS（Reliability, Availability, Serviceability）系统用于：
- 监控各 rank 的健康状态
- 检测故障并报告
